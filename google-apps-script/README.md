# TAXIAPP → Google スプレッドシート連携（初回のみ）

対象： [TAXIAPP_補助簿印刷_新運用テスト_20261016](https://docs.google.com/spreadsheets/d/1tBoPSm_hni7VE_TcP3n0gvGXexX9G4KSKUD3xPJZNS4/edit)

**アプリ（スマホ）から印刷はしません。** スマホから乗務データを受信して保管し、別のPCで印刷対象の乗務を選びます。

## 初期接続

1. PCで上のGoogleスプレッドシートを開き、「拡張機能」→「Apps Script」を選びます。
2. 既存のスクリプトやマクロは消さず、左側の「＋」→「スクリプト」で **TAXIAPP_Bridge.gs** を追加します。
3. [Code.gs](./Code.gs) の内容をすべてコピーし、TAXIAPP_Bridge.gs に貼り付けて保存します。
4. 上部の実行する関数で `setupTAXIAPP` を選択して「実行」。Googleが求めるスプレッドシートの権限を許可します。
5. ダイアログまたはApps Scriptの**実行ログ**に出た **TAXIAPP接続キー** を控えてください。キーはGitHubや他の人に公開しないでください。
6. 「デプロイ」→「新しいデプロイ」→ 歯車アイコンの種類から「ウェブアプリ」。**実行ユーザー：自分**、**アクセスできるユーザー：全員** を選択してデプロイします。Googleの確認画面が表示されたら承認します。
7. デプロイされた **https://script.google.com/macros/s/.../exec** のURLをコピーします。
8. スマホの [TAXIAPP](https://elpapityo.github.io/TAXIAPP/) で「設定 → Googleスプレッドシート」を開き、WebアプリURLと接続キーを入力します。送信方法は最初「必要なときに手動送信」を選択しておいてください。
9. 「この乗務をGoogleへ送信」を押し、**受信確認済み** と表示されたらGoogleシートの「TAXIAPP_乗務一覧」で件数を照合します。問題なければ「入力後に自動送信する」に切り替えます。

> Webアプリを更新したら「デプロイ」→「デプロイを管理」で新しいバージョンに更新してください。GitHubの更新だけではApps Scriptの公開版は更新されません。

## 別PCからの印刷

1. Googleシートの **TAXIAPP_印刷操作** を開き、**B17** で「10/16 07:34出庫・営業1件」のような表示から乗務を選びます。**B15にチェックを入れると最新乗務を自動選択**します。最新版Apps Scriptの「TAXIAPP 印刷 → 最新乗務を選択」からもワンクリック選択できます。内部の長い乗務IDは非表示です。
2. **選択した時点で**「補助簿印刷用」（1〜36件）と「補助簿印刷用_2頁」（37〜60件）に直接反映されます。旧「日報」「チケット」の集計式は使用しません。
3. 日付・出庫時刻・乗務員名・金額・金種を確認し、**別PCから**印刷します。上部メニューの「TAXIAPP 印刷 → 印刷対象とメーター売上を確認」は任意の照合操作です。
4. **最初の一回は試し刷り**を行い、用紙の位置・余白、金額、決済種類、乗降時刻が正しいかを照合します。

### 2026年10月16日：日本時間表示・最新乗務選択

- 乗務一覧の出庫・入庫日時は **日本時間（例：2026/10/16 07:34）** で表示します。Googleシートのタイムゾーンは `Asia/Tokyo` です。
- 新しい乗務が上になるように受信データを整理し、表示用のドロップダウンも新しい順にしています。
- 「最新乗務を表示（チェックで切替）」にチェックを入れると、B17の手動選択よりも新しい乗務を優先します。チェックを外せばB17で過去の乗務も選択できます。
- **最新の Apps Script コードに置き換え、管理デプロイから新バージョンを公開してください。** 旧公開バージョンは出庫日時をUTCのISO文字列で上書きし、旧方式の「乗務ID」をB17に期待するため、表示やメニューが合わなくなります。
- 帳票の罫線はバックアップと比較して保持されていることを確認しました。乗降時刻は文字列の左寄せではなく、元の帳票どおり時刻形式・右寄せに戻しています。

### 2026年10月16日：印刷表示の修正

- 紙の補助簿が旧テスト売上を混ぜないよう、**TAXIAPP_印刷データ／乗務一覧／決済内訳／集計** の新しいデータを直接参照するよう変更しました。
- 1件目の確認例：メーター3,200円、現金納金2,700円、QR500円、GO手数料200円、総入金2,900円。現金＋QRの複合決済も表示します。
- 乗務IDを変えれば、両方の印刷用帳票の数値を切り替えられます。未記録の営業欄には古い値を表示しません。
- 旧ファイル全体のバックアップを作成してから、不要な複製・調査タブを削除しました。歴史的な計算用タブと受信保管用タブは、既存の処理や過去データの保護のため非表示にしています。
- この修正に合わせて [Code.gs](./Code.gs) の **applySelectedPrintShift** も更新しました。既にv1を公開済みの場合は、Apps Scriptのコードを最新版へ差し替え「デプロイ → デプロイを管理 → 編集 → 新バージョン」で更新してください。既存のWebアプリURLと接続キーはそのまま使用できます。コードのアップデートは、シートへの今回の表示修正に必須ではありませんが、古い参照元へ書き込む動作を防ぐため推奨します。

## 「指定の乗務IDが見つかりません」と表示された場合

2026年10月16日の修正で、乗務選択欄の表示を `shift-...` から「10/16 07:34出庫・営業1件」のような表示へ変更しました。古い印刷用スクリプトを実行すると、B17に内部IDを書き込んでしまい、隠しセルC17が正しいIDを読み取れずにエラーとなる場合がありました。

- **すでに受信した乗務データは消えません。**
- 「TAXIAPP_印刷操作」の **B15「最新乗務を選択」** にチェックを入れてください。B17は分かりやすい表示に戻っています。
- **印刷対象を選ぶだけで補助簿2枚は自動更新されます。** 上部メニューの「選択乗務を補助簿へ反映」は不要です。
- 今後は [Code.gs](./Code.gs) の最新版を正しいApps Scriptプロジェクトに貼り付け、保存後「デプロイを管理 → 編集 → 新バージョン」で公開版を更新してください。最新版ではB17に長いIDを書き戻さず、C17の内部IDを使って照合します。確認操作でもB3/B4/B18/B19の自動計算式を消さないようにしています。

## 安全対策

- 印刷用シートのセル幅・高さ・結合・罫線は変更しません。
- 既存の旧参照元「日報」「入力_RAW_実車」は新版の印刷には使用せず、過去データ保護のため非表示で保存しています。
- スマホの端末内保存は継続。Google送信失敗でローカルデータを削除しません。
- 同一の乗務IDを再送信すると内容を更新し、他の乗務を削除しません。
- 送信キーはスマホ端末内だけに保存し、JSONバックアップには含めません。
- Apps Scriptのデプロイを許可した人以外はGoogleへの書き込みができないよう、送信時に接続キーを照合します。ただしキーを知った人には書き込み権限が生じるため、キーは厳重に保管してください。
- 接続テストと紙の印刷が終わるまで、本番帳票として使わないでください。
