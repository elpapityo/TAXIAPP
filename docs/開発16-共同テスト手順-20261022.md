## 管理者本人Firestoreの最優先・開発用画面（PR #119）

1. PR #119の開発ブランチのコードを別のフォルダへ取得。**公開中のGitHub Pages URLはmainのため、検証用に使わない。**
2. Windowsの開発用PCでPR #119の最新版ZIPを完全に展開し、**`start-admin-firestore-preview.cmd` をダブルクリック**する。ブラウザに **v0.3.126（開発版 PR #119）** と表示される。Python 3.9以降またはNode.jsがあれば、サーバーが正常に起動した**後**でブラウザを開く。検証中は黒いBAT画面を閉じない。**画面が開かない／サーバーが終了する場合は黒い画面にエラー理由と手動URLが残る**ので、その内容を確認する。以前のZIPから起動したサーバーが8787番ポートを使用中なら、古い黒い画面を閉じて再実行する。どちらの実行環境もなければ追加インストールせず停止する。検証URLは `http://localhost:8787/?adminFirestorePreview=1&build=v0.3.126-pr119`。localhost以外では検証ボタンを出さない。外部公開や本番デプロイはしない。**mainのZIPではなくPR #119のブランチZIPが必要**。
3. **管理者本人のFirebaseアカウント**でログインし、操作端末になっていることを確認。「設定 → 日報原本の保存先 → 本人Firestoreの検証を開始」を押す。これは正式なFirestore切替ではなく、`taxiapp-admin-firestore-preview-v1-{uid}` の独立した端末記録を使う。旧Googleの保存先マニフェスト、既存スマホ原本、Googleの保存先は変更しない。
4. **合成の乗務のみ**出庫→営業記録→支払確定→入庫。「設定 → 日報原本の保存先 → 現在の乗務をFirestore読戻し確認」で本人UID配下の**乗務ID・更新番号・内容一致**が出ることを確認する。通信が失敗したら成功表示にはならず、端末コピーを保持する。
5. 「営業履歴」で日付を指定して同じ合成日報を取得し、直近入庫済みで端末側にも残っている乗務を編集する。**端末とFirestoreの確認済み版が一致するときのみ**編集を許可。保存するとCAS更新、サーバー読戻し確認、端末の直近原本の更新番号引継ぎを行い、現在乗務とGPS・設定を上書きしない。
6. 検証が終わったら「検証を終了して旧Google運用画面へ戻る」を押す。検証中のFirestore原本・端末控えは削除せず、正式な管理者原本は従来のGoogleのまま。
7. Firebase Authenticationのlocalhost許可・Firestore Rules/IAMの現状が不十分で、**実Firestoreへ接続できない場合はそこで停止**。本番Firebaseの設定を自動変更せず、必要な設定・影響範囲・復旧方法を示して個別承認を得る。実Firestoreへ保存できていない限り、本番／実機動作確認済みとは報告しない。
