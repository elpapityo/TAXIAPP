# TAXIAPP：Googleログインと設定データの引き継ぎ（試験導入）

## 2026-10-17：v0.3.45 端末の操作権（後からログインした端末が優先）

- 端末1台が **操作可能**。別のPC・スマホで「操作用ログイン」または「この端末で操作する」を実行すると、新しい端末が操作可能、前の端末は閲覧専用になる。
- 「閲覧でログイン」は、他の端末の操作権を奪わない。自動復元されたGoogleログインも、過去の操作セッションが残っていない新ブラウザでは閲覧専用から開始する。
- 同じブラウザタブを再読み込みしても操作権を奪い返さない。古いタブが権限を失った場合は、再読み込みしても閲覧専用のまま。
- 閲覧端末では入力・保存・Google Apps Script同期・GPS測位をクライアント側で停止。履歴・設定などの閲覧とタブ移動は可能。ただし**閲覧用の端末データは自動でクラウドの最新営業記録へ更新されるとは限らない**。
- Firestoreの `deviceSessions/{uid}` ドキュメントだけ変更通知を購読する。追加の定期ポーリング・ハートビートは行わない。**設定の取得は操作端末のログイン開始時・変更時（または長い非表示から復帰したとき）だけ**。
- 操作権を奪われた古い端末のFirestore設定書き込みは `writerSessionId` を検査するサーバールールで拒否。ただし古いv0.3.44以前のブラウザコード、Google Apps Script単独の共有接続キーでの書き込み、切替直前の送信済み通信まではFirebase側で停止できないため、両端末を最新版へ更新し、GAS側の認証統合も将来実施する。
- 端末切替の即時性にはFirebaseセッションドキュメントの変更通知が必要。切断中の端末は切替通知を受け取れないため、完全なサーバー強制は将来のGAS認証統合まで保留する。

### Firebase管理者の切り替え手順

1. [最新のFirestoreセキュリティルール](https://github.com/elpapityo/TAXIAPP/blob/main/firestore.rules) をFirebase Consoleのルール欄へ全文反映し「公開」。
2. PC・スマホの両方をTAXIAPP v0.3.45で更新。
3. 先にPCで「この端末で操作する」、次にスマホで「この端末で操作する」。
4. スマホは操作可能、PCは閲覧専用の表示になるか確認。
5. PCで閲覧タブを開けること、編集・Google自動送信・GPS測位が止まることを確認。
6. 確認後、閲覧端末の「この端末で操作する」で操作権を取り戻せるか試す。いずれも現在の乗務・編集を中断し、安全な停車時に行う。

## 2026-10-17：v0.3.44 以降の通常操作（自動設定同期）

- **従来の日報アプリのURLを開き、Googleログインするだけ。** 同じGoogleアカウントでログインした端末間では、乗務員名・待機所・待機所座標・料金・表示・入力などの設定を自動的に照合・保存する。
- 通常の設定画面で変更すれば自動同期される。旧「設定を初回保存」「クラウドを再確認」「暗号化バックアップ→取り込み」の操作は、**新たな変更ごとに不要**。旧移行画面は復旧用に残す。
- オフライン中は端末保存。再接続時に同期。同じ項目を別端末で同時に異なる値へ変更した場合は、値を失わないようクラウド上書きを止め、画面上部に通知。
- 初めて新ログインに紐づける端末はクラウド設定を基準とし、端末固有の待機所だけ統合する。クラウド設定適用前の端末設定はローカルへ自動控えを残す。
- 営業記録・GPS履歴は今回の設定同期で編集しない。**従来の乗務単位のGoogle Apps Script双方向同期は別経路**のまま。
- 既存のGAS接続キー・WebアプリURL・連携先シートURL・端末同期モード、およびブラウザのGPS許可は端末固有。新端末へ秘密キーを自動コピーしない。
- 利用停止中アカウントは同期不可、別Googleアカウントへ端末データを不用意に転送しない。一般利用者の招待/個人別日報の本体側認可は引き続き開発対象。

## 以下は旧方式の移行・復旧手順（通常は不要）

## 現時点で実装したこと

- 既存の日報アプリ `index.html` は変更せず運用継続。
- 既存のGoogle Apps Scriptによる**乗務単位の双方向同期**は従来どおり動作し、今回の操作では乗務データを更新しない。
- Googleログイン済みの管理者が `login.html` から、端末にある設定 `model.prefs` を本人UIDの `accountSettings/{uid}` に**初回保存**できる。
- 既に保存がある場合は初回保存ボタンを無効化し、Firestoreトランザクションでも二重作成を拒否。
- 別端末へ設定を適用する場合、端末内の全乗務・設定・Google接続キーの**暗号化バックアップ**を先に書き出し、保存確認後だけ適用。
- 適用時に**乗務と途中入力、GPS履歴を保持**し、`prefs` だけ更新。待機所の候補は両端末を重複なしで統合、位置座標も統合する。候補が30件を超えると安全のため中止。
- GASのWebアプリURL・送信先シートURL・同期モード・送信モードは、その端末の値を保持。秘密キー・パスワード・トークンはFirestoreへ送らない。
- ブラウザの位置情報許可は設定だけでは引き継げず、端末ごとに許可する。

**未実装**：この設定保存は現時点で**手動**。本体でログインするだけで常時設定を双方向自動同期する機能や、アプリ自体の認証必須化はまだできていない。一般利用者の招待コード登録、各人のDriveフォルダーへの自動書き込みも今後。

## 初回に必要な管理者操作

1. Firebase Console → TAXIAPP → Firestore Database → **ルール** を開く。
2. [GitHubの最新版 firestore.rules](https://github.com/elpapityo/TAXIAPP/blob/main/firestore.rules) を丸ごとコピーして貼り付け、**公開**。変更箇所は `accountSettings/{uid}` の本人アクセスだけで、既存の `admins`・`users`・既定拒否は維持。
3. [ログイン移行ページ](https://elpapityo.github.io/TAXIAPP/login.html) で、既に管理者登録されたGoogleアカウントにログインする。
4. **待機所と乗務員名が正しく入っている端末**で、確認画面の待機所件数を照合し、**「この端末の設定を初回保存」**を押す。空のPCから誤って保存しない。
5. スマホ・PCのもう一方では、同じGoogleアカウントにログインし、クラウド設定を確認する。
6. 取り込む前に現在の端末で暗号化バックアップをダウンロード。パスワードを控えたうえで保存確認し、「クラウドの設定を取り込む」を押す。
7. 従来の日報アプリを開き直し、待機所・乗務員名・料金・表示・日報件数・Google同期状態をそれぞれ確認する。

## 技術とデータ保護

- Firestore保存形式：`{format:'TAXIAPP_ACCOUNT_SETTINGS_V1', schemaVersion:1, prefs:..., updatedAt:serverTimestamp()}`。
- Firestoreセキュリティルールは、認証された本人で、`admins/{uid}.enabled=true` または `users/{uid}.status='active'` の場合にのみ本人の設定を読み書きできるようにする。全件列挙・削除は禁止。
- Google認証が成功しても、Firestoreルールが未公開のときは**設定の送受信はできない**。UIに設定案内を表示する。
- 端末保存はIndexedDBの同じ `state/taxiapp`、必要な場合のみ従来どおりlocalStorage `taxiapp-v1`。取り込みは最新データとの一致を検査してからトランザクションで更新し、途中で記録が変化したら中止。
- 暗号化バックアップにはAES-256-GCM＋PBKDF2を使用。ファイルやパスワードは公開GitHub、公開オプチャ、共有リンクには置かない。
- 管理者以外の一般利用者用の機能は、複数利用者のID隔離・退会後の停止等の最終実装が完了するまで公開しない。
