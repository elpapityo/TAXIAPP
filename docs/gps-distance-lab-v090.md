# GPS距離ラボ v0.9 — 保存済み地点が「取得済み」なのに「—」の不具合対応

## 実際の画像
- Chrome外部ブラウザ `http://127.0.0.1:48764`
- 計測地点2・3・4が「取得済み」なのに、GPS累計・GPS区間・補正後距離が「—」。記録時刻は「未取得」。
- 地点2には200、地点3には300という手入力が保存されている。入力単位はkmなので200は200kmであり、200mなら0.200kmが正しい。

## 原因と修正
- 旧Web側の `derive` がある地点のGPS未記録で `valid=false` にし、後続のGPS数値を全件無効にしていた。**GPS累計はAndroid計測アプリからの累積値**なので、未取得の地点が途中にあっても、後で保存されたGPS値は前回の有効GPS累計または基準点から差分を計算できる。ただし欠測した地点個別の区間を勝手に分割しない。
- `gps!==null` だけで「取得済み」と表示し、`at` がnullでも日時を検査していなかった。日時のない記録は **「再取得」** を表示し、保存済みの元のGPS値・手入力補正を保持。履歴は勝手に削除しない。
- 値がスタートより小さい等の不整合はエラーを具体表示し、再取得で正常値へ更新可能。後続保存済み地点より大きい現在GPSを、過去の地点へ誤って割り当てない。
- 手入力欄に **200mは0.200と入力** する説明を常時表示。アプリ側のGPS計算アルゴリズムは変更しない。

## データの引き継ぎ
- ローカルブラウザ接続先は**従来と同じ127.0.0.1:48764**。
- HTML内の `localStorage` キーも従来の`gps-distance-lab-browser-v080`のまま。これまでの0km基準、GPS記録、手入力200・300を保持し、新しいWeb画面で自動的に再計算。**「初期化」を押さないこと**。
- APKはAndroid debug署名の衝突を防ぐため別アプリ`jp.taxiapp.gpsprototype.distancelabv090`。旧v0.8のGPSを停止してからv0.9のGPSを起動する必要がある。
- 外部Chrome使用、追加タブなし、端末内通信のみ、Google有料APIなし。実走行での精度とAndroid OS依存挙動はまだ未検証。

## 検証項目
- 第1地点のGPS欠落、第2地点GPS累計1.572・日時なし、第3地点1.672・日時あり（基準1.372）でも、第2地点0.200km・第3地点0.300kmが表示される。
- 第2地点の記録日時がないので「取得済み」ではなく「再取得」が表示される。
- 車両距離手入力200km・300kmは上書きせず保持される。
- 過去の記録済み地点を現在のGPS値で不正に上書きしない。
