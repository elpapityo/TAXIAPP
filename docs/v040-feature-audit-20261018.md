# TAXIAPP v0.4.0移行・第1段階 機能棚卸し（2026-10-18）

対象：GitHub mainの本体 `index.html`（表示タイトルv0.3.49）と `ui-preview.html`（UI試作4方式）、独立JS、テスト。参考：プロジェクトの「タクシー営業管理アプリ 統合実装仕様書」「複数人利用・機能カスタマイズ仕様追加依頼」「Taxi-Board参考仕様調査」。

## 0. 判定基準・重要な区別

- **コードあり**：v0.3.49本体に実装・表示・処理の入口が確認できる。端末・実運用で正常動作確認済み、という意味ではない。
- **要実機・結合検証**：処理はあるが、GPSの継続性、Google同期、紙帳票、料金の正しさ等は公開・実運用前の検証が必要。
- **試作のみ**：`ui-preview.html` では入力デモを表示するが、日報保存・GPS・精算計算・サーバー同期へは未接続。
- **未実装・将来候補**：仕様書にはあるが、本体の該当機能について今回のコード調査では完成した処理を確認できない。
- **区別する2軸**：表示方法「1画面／段階／詳細／従来」と、入力項目セット「簡単／標準／フル機能」は別設定にする。4方式＝機能4セットではない。
- **バージョン**：v0.3.49にはFirestoreによる1端末操作権の試験実装がすでに存在。ユーザー指定により**正式なサーバー認証方式を含む新本体はv0.4.0から**として扱う。棚卸しだけで本体番号を上げない。

## 2. 現時点で未実装または十分な証拠がないもの（v0.4.0本体へ無断追加しない）

- **ユーザー別「簡単／標準／フル機能」テンプレート＋項目ごとON/OFF**：プロジェクト追加仕様で要求。現行本体には表示・キーボード等の個別設定はあるが、入力項目すべてを利用者ごとにON/OFFする共通仕組みは確認できない。
- **4つのUIを本体の保存／精算／GPSと連結**：現状全方式がプレビューのみ。UIモードを切替えても同一の未保存・保存済み営業情報にアクセスできる機構は未実装。
- **会計の税込／税抜の「表示だけ」切替**：要望あり、現行コードで全画面に対する正式な切替仕様は確認できない。計算・保存値は絶対に変更しない設計で追加。
- **利用者別・会社別の金種／手数料の完全なテンプレート**：現行の基本設定とは別に新設計が必要。
- **週間／月間／年間の売上グラフ、目標達成率、エリア別平均時間単価**：統合仕様書の目標・追加候補。現行の当日集計や参考試算と区別。
- **顧客管理・タスク／予約表・応援機能・任意位置共有・ランキング・メッセージ**：共同利用の将来候補。利用者同意・データ境界・費用の検討が必要。
- **雨・鉄道遅延速報**：外部データ源・提供範囲・料金の比較が必要。
- **走行軌跡の完全な背景継続、実車メーターとGPSの一致保証**：未確認。現行GPS試験実装は表示中の位置取得を基本にし、欠測は推測で埋めない。
- **複数人が独立したデータを安全に扱う本番アクセス制御**：現在の単独アカウント操作権試験実装と区別して設計する。
- **カーナビ・目的地への経路案内は不採用**：統合仕様書に従い実装対象外。

## 3. v0.4.0への安全な移植順

1. **保存・計算を固定**：`model.shifts`、`activeId`、各`draft.raw` A〜AR列と補助meta、既存GO/Uber／高速／割引／決済計算を仕様上の不変条件にする。まず既存データのバックアップと回帰テストを確認。
2. **共有操作層の抽出**：出庫・待機・迎車・実車・降車・精算保存／取消をUIから分離し、従来画面でも同じ処理を呼ぶようにする。バックアップ互換を維持。
3. **新「1画面入力」を最初に接続**：営業状態に応じた主要操作は1画面。GPS・時間・ODOはその場で取得。高速、分割支払、人数、詳細RAW項目などは展開して編集できる。狭い340px／300pxでは基本操作を1列。
4. **「段階」「詳細」「従来」を共通層へ接続**：保存データは1つ。入力画面を変えてもドラフト・訂正・集計は変化させない。従来は互換性比較の基準として残す。
5. **設定の2軸分離**：入力画面方式（4択）×入力項目テンプレート（簡単／標準／フル機能）＋個別表示設定。OFFにした項目の既存値を消さず、未入力項目を推測で補完しない。
6. **認証・同期の本番化**：操作端末1台・閲覧端末はログイン時と手動更新時だけ受信、Googleの競合データ保護。異なる利用者のデータ分離は別途検証。
7. **本番移行前の実機テスト**：スマホ393px、折りたたみ半画面300〜380px、全画面673px、タブレット834px、各縦横。待機→迎車キャンセル、実車→高速→複合精算、入庫取消、モード切替中の未保存ドラフト、オフライン復帰、Firestore操作権切替、GPS欠測・補正、60件制限、紙の日報照合。
8. **テスト・移行成功後に本体v0.4.0へ**：今回の棚卸し時点で本体v0.3.49を改変しない。

## 4. 移行で絶対に守る条件

- 本体の既存営業データ、過去の乗務、精算金額、Googleシート帳票、接続キーをUI開発のために消去・再生成しない。
- 値の保存と、画面表示（見せ方、税込・税抜、表示／非表示、モード）を切り分ける。
- 編集できない閲覧端末からは、営業データを書き込まない。
- 既存保存形式を改訂する場合は、旧データ読込とロールバックをテストしてから実施。
- コードに処理があることと、車載実機で安定して使えることを同一視しない。
