## 1. 日付・乗務開始・原本の直接入力

| セル | 原本の入力／式 | 意味・注意 |
|---|---|---|
| B1 | 日付の手入力 | 乗務日。原本では日付型 |
| B2 | `=TEXT(B1,"ddd")` | 曜日 |
| B3 | 直接入力（例：晴） | 天候。現在のTAXIAPP乗務データには専用項目未確認 |
| C2 | 直接入力（時刻） | 出庫／乗務開始時刻に相当 |
| D2 | `=IFERROR(LOOKUP(9^9,I4:I67),"")` | **営業行の最後のI列（乗車時刻）**を取得。入庫時刻ではない |
| H2 | `=IF(D2="","乗務時間",D2-C2+IF(C2>D2,1))` | C2からD2までの経過時間。日付跨ぎ補正あり。最終入庫までの勤務時間とは限らない |
| N1 | 年（直接入力） | 乗務年 |
| AX1 | 車両番号と思われる直接入力 | 固有値を一般仕様に固定しない |
| AZ1 | 入社年等の自由な表示 | プロフィール表示であり計算はしない |
| AE1, AE2 | TRUE/FALSEの入力 | 意味未確認。表示・転記対象にはしない |

元ファイルのスプレッドシートタイムゾーンは `America/Los_Angeles`。TAXIAPPと印刷用の時刻基準は日本時間を優先し、元ファイルのタイムゾーンをそのまま引き継がない。

## 2. 件数・メーター売上・キャンセルの照合

| セル | 実際の数式 | 読み解き |
|---|---|---|
| K1 | `=COUNTIF(P4:P67,"キ")` | 日報の支払種別P列が「キ」のキャンセル件数 |
| C3 | `=COUNTIF(G4:G67,"G")+COUNTIF(G4:G67,"D")+COUNTIF(G4:G67,"乗")+COUNTIF(G4:G67,"U")+K1` | G/DiDi/流し/Uberの件数＋キャンセルの件数。高速の単独記録等を含めない |
| G3 | `=COUNTIF(G4:G67,"乗")` | 流し営業（区分「乗」）の件数 |
| M3 | `=SUM(M4:M67)` | 通常営業メーター売上の合計（キャンセルの仮想700円は含めない） |
| I3 | `=(700*K1)+M3` | 車両のメーターとの照合用にキャンセル迎車料700円×件数を加算した**参照値**。売上計上はしない |
| H3 | `=IF(I4="","回数平均",M3/C3)` | 1記録当たりの平均メーター売上。**分母はキャンセルを含むC3**なので、実車営業だけで割る平均とは異なる |
| U3 | `=COUNTIFS(G4:G67,"G",P4:P67,"<>G")*200` | GOで、支払種別が「G」でない営業を200円×件数で集計。金種別の車内回収条件がある |
| AY23 | `=COUNTIFS(G4:G67,"G",P4:P67,"<>G")*200` | U3と同じGO手数料 |
| AY24 | `=K1*700` | キャンセルによるメーター照合用参考額 |
| AZ22 | `=IF(I3=M3+AY24,"〇","×")` | キャンセル参考額の**内部式同士の整合チェック**。**車両メーターの実測値との独立照合ではない**点に注意 |

**既存の実装：** TAXIAPPには `totals().meter`, `totals().cancels`, `meterCheckValues()` による売上とキャンセル700円の参考値の分離がある。GO手数料は複合決済を別に管理するため、旧式の単一金種P列だけで再計算せず、アプリの `goCollectionFee()` による精算ロジックを優先する。

## 3. 距離・実車率・免除距離

| セル | 実際の数式 | 読み解き |
|---|---|---|
| S3 | `=SUM(S4:S67)` | 空車（迎車）区間距離の合計 |
| T3 | `=SUM(T4:T67)` | 実車区間距離の合計 |
| M1 | `=S3+T3` | 上記の合計距離 |
| F1 | `=IF(H4="","実車率",(T3/M1))` | 実車率（実車距離／合計距離） |
| O2 | `=IF(H4="","",T3/(S3+T3))` | 実車率（F1と同趣旨） |
| I1 | `=IF(H4="","キロ単価",M3/M1)` | 1kmあたりメーター売上 |
| P2 | `=SUM('入力_RAW_実車'!AK2:AK125,'入力_RAW_実車'!Y2:Y125)` | RAWの空車高速・実車高速の「免除距離」を加算 |
| M2 / P3 | `=275+P2` | 設定された「275km＋免除距離」という参考上限（業務上の意味は未確認） |
| F3 | `=M2-M1` | 275km＋免除距離に対する残距離 |
| H1 | `=IF(H4="","MAX売上",I1*(265+P2))` | 「265km＋免除距離」にkm単価を掛けた推計MAX売上。M2の275kmとは基準が異なるので自動解釈・法的判断をしない |

距離計算の基点は日報の行4以降を参照：
- 最初の空車距離 `S4=H4-0`。
- 次の空車距離 `S5=H5-N4` （次の乗車距離－前回降車距離）。
- 実車距離 `T4=N4-H4`, `T5=N5-H5`。
- よって**最終営業の降車～入庫までの空車距離はS3だけでは計上されない**。GPS全行程の実車／空車区分と違う場合がある。
- トリップ距離の補正や測位中断がある場合、差分を無条件に実車／空車へ分類してはいけない。
- 除算は分母0なら「未計測」等の明示で保護する。

## 4. 時間・稼働効率

| セル | 実際の数式 | 読み解き |
|---|---|---|
| R2 | `=SUM(C4:C67)` | 営業行の空車・次乗車までの時間を合計 |
| R3 | `=SUM(R4:R67)` | 営業行の待機時間列の合計 |
| I2 | `=IF(D2="","平均空車時間",SUM(C4:C67)/C3)` | 記録件数あたり空車時間。キャンセルを含む件数で除算 |
| O3 | `=IF(I4="","",R3/H2)` | 待機時間 ÷ 乗務時間 |
| U2 | `=IF(M4="","￥/h",M3/(H2*24))` | メーター売上 ÷ 乗務時間（時間単位への変換） |
| D1 | `=U2` | U2の時間売上を上部に再表示 |

TAXIAPPには乗務出庫・入庫時刻、実車時間、待機区間、空車・迎車等の参考時間がある。ただし**旧日報のD2は最終乗車時刻、待機のR3は旧日報の算出方法**であり、TAXIAPPの実時間とは同一でない。時間平均を採用する際は「旧日報式」と「実際の出庫～入庫ベース」を区別する。

## 6. 元RAW・現TAXIAPP印刷ファイルとの関係

- 元の「日報_RAW」ファイルには「日報」タブに22件の営業が存在し、上部3行がその内容を集計していた（2026-10-14例）。
- 一方、元ファイルの「入力_RAW_実車」にはこの確認範囲で見出し行があり、2～4行の実データは空欄。**日報の営業行は元RAWに完全自動連動していると推測しない**。式で見えているXLOOKUP対象は主に高速代等の補助参照。
- 現在のTAXIAPP印刷用ファイルでは旧「日報」タブの上部は数式が残るが、2026-10-16のサンプルに対して **C3=1、M3=3,200円**。同じファイルのTAXIAPP本体側は3記録・メーター6,400円なので、現状この旧「日報」タブは全データ同期の確認済み帳票ではない。
- 旧「日報」タブの1～3行目だけを残したまま自動表示するのではなく、**TAXIAPPの1乗務IDに対応する全記録を単一データソースにする**ほうがデータずれを防止できる。
- Google同期原本や既存シートの書式・数式を変更する前に、適用対象が**スマホの日報集計画面なのか、印刷用シートなのか、その両方か**を決定する。

## 7. 移植の優先順位

1. **現在のアプリで確実にできる：** 日付・曜日・出庫時刻・実車件数・キャンセル件数・メーター売上・キャンセル参考700円・GO車内回収手数料・実車率（GPSトリップの欠測がない場合のみ）・時間売上。

3. **仕様確認後に移植：** 265/275kmと免除距離の意味、MAX売上、年計N40/O40/N41/O41の業務上の位置付け、旧日報「実売」定義、天候・車両プロフィールの表示先、単一金種依存の古い預かり精算。

旧式の文字列「キ（キャンセル）」は金額0円のまま件数のみ計上。700円はメーターの参照用であり売上・納金には計上しない。GO手数料は納金対象、Uber配車手数料は納金対象外の現行ルールを維持。

## 8. 採用仕様：1日の基準13時間・275km＋高速免除（2026-10-16）

**TAXIAPP v0.3.27 に実装。** 原本では `H1=I1*(265+P2)` という参考式もあるが、現行TAXIAPPの試算距離は乗務員が指定した **275km＋高速免除距離** を採用する。元ファイルの265kmを上限として再利用しない。

- **業務時間の基準：13時間。** 出庫日時 `shift.startedIso` から実時間を測定し、入庫後は `shift.endedIso` で固定する。終了日時がない過去の入庫記録は、現在時刻まで勝手に加算しない。
- **時間の残り：** `max(0, 13時間 - 出庫からの実時間)`。13時間超過時は超過時間を別表示。13時間経過したことを理由に乗務を自動終了しない。
- **距離上限：** `275km + SUM(実車高速の免除距離 Y) + SUM(空車高速の免除距離 AK)`。各区間の免除距離は `deriveRaw()` により原本仕様に準拠して高速区間走行距離の75%を計算する。実車・空車高速の両方を加算し、高速道路を走った距離全体をさらに二重加算しない。
- **走行実績：** 出庫・入庫トリップの差を優先。入庫前は、検証済みGPS距離、入力済みトリップ値、直近降車時トリップの順で使用し、入力元や未含有区間を明示する。GPS欠測が未補正の場合は自動試算しない。
- **時間あたり売上：** `メーター売上 ÷ 出庫からの経過時間(h)`。時間あたり売上×13時間は**13時間換算の参考売上**。30分未満・営業0件は試算を表示しない。
- **1kmあたり売上：** `メーター売上 ÷ 入力済みの走行実績(km)`。
- **距離上限での売上試算：** `（メーター売上 ÷ 走行実績km）×（275km + 高速免除km）`。未計測／欠測なら「未計算」表示。走行距離がゼロなら除算しない。
- **売上・納金との分離：** キャンセル700円はメーター照合参考値にのみ含み、時間・距離の売上単価には含めない。GO納金200円、Uber配車料などの精算区分、既存データ／スプレッドシートの式は変更しない。
- **画面：** 「乗務入力」の基準パネル、「営業状況」「日報集計」の折りたたみ画面の詳細分析で表示。画面が表示中は業務経過時間・残り時間・距離／試算を1秒ごとに更新する。終了した乗務は固定値。
- **既存の任意帰庫時刻：** 過去の「任意の帰庫予定時刻による参考試算」は折りたたみ式の別機能として保持。13時間基準を上書きしない。
- **テスト：** `tests/daily-reference.test.js` で時間13h、日付跨ぎ、入庫後の固定、実車・空車高速免除の合算、275km＋免除の売上試算、距離未入力、GPS欠測を確認。

この13時間・275kmは業務管理上の計算基準。労働法上の時間・走行距離制限や運賃・売上の実際の上限を断定するものではない。実際の売上は需要・運賃・稼働状況等で変わる。
