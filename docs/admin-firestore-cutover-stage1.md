# TAXIAPP 管理者Firestore原本化：第1段階（検証用・本番切替なし）

## 前提
決定済みの将来方針は、**全利用者のFirestore原本への統一、Google Sheetsの印刷専用化、利用者が選ぶサーバーゴミ箱**。詳細は Issue #105 / #111 および PR #112 の `docs/firebase-originals-print-only-trash.md` を参照。

この段階では**本番運用の管理者ログインは旧Google Sheets保存を維持**し、データ移行・本番ルール公開・Apps Script変更・既存のSheetsデータ操作を実施しない。

## 今回実装したもの
1. `account-diary-store.js` に管理者用の **明示的かつ初期値OFF** の `storageBackend: 'firestore'` オプションを追加。
   - 従来どおり `admin: true` のみでは `kind() === 'legacy'`、Firestore APIは使えない。
   - 認証済み管理者本人のFirebase接続に対して、呼び出し元が明示的に `storageBackend: 'firestore'` を渡した場合だけ、本人UIDの `privateDuties/{uid}/shifts` を利用する。
   - Firestore側の本人UID制限、CAS、端末編集セッションは従来のまま維持。他ユーザーの原本は参照させない。
   - **`index.html` の呼び出し元は変更していないため、通常の管理者アプリ操作からこのオプションは使われない。**
2. `admin-firestore-cutover.js` に **読み取り済みの合成/検証データを使う純粋な事前判定器** を追加。
   - 入力：管理者本人UID、旧保存元の乗務一覧、本人UIDのFirestore乗務一覧、明示的に選択した乗務ID。
   - 出力：選択件数、除外件数、すでに存在する同ID、内容不一致、別IDで乗務時間の重複、時刻未確認、移行候補。
   - **いかなる候補も自動アップロードしない。** 結果の `migrationAuthorized` は常に `false`。
   - 例えば保存元5件から必要2件だけ選んだ場合は、残る3件は移行候補に含めない。
   - 同一UID以外を入力した場合や不正な日報ID・重複IDは拒否。

- PR #110 の未同期日報保護と同一ID競合許可制をレビューして統合方針を確定する。
- 管理者のFirestore原本から**選択した1件だけ**既存Sheets帳票へ印刷用に一方向反映する処理を実装し、紙帳票・式・既存印刷マクロを比較。

## 2026-10-21 第6段階：印刷専用ステージの独立した追記試作（本番未接続）

### 実装範囲とデータ保護

- `google-apps-script/PrintOnlyStageDraft.gs` に、**本番 `Code.gs` に参照されない独立した試験用実装**を追加した。`doPost()` に新しい操作種別を追加していない。HTMLアプリにも呼出しを追加していない。Apps Scriptへの実デプロイ・Googleシートへの実書込はしていない。
- 仮の転送先タブは **`TAXIAPP_印刷ステージ_V1` のみ**。このタブは現在の本番シートに作成していない。既存の `TAXIAPP_同期原本`、`TAXIAPP_乗務一覧`、`TAXIAPP_印刷データ`、`TAXIAPP_印刷操作`、`補助簿印刷用`／`_2頁`、競合保管庫、版管理シートへの書込はコード上拒否する。
- `printStagePrepareV1_()` は、管理者の日報パケット `TAXIAPP_SHIFT_V1` とFirestore更新番号から**印刷に必要な項目だけ**を `TAXIAPP_PRINT_PROJECTION_V1` へ変換する。営業明細は従来GASの14列印刷データから先頭の乗務IDを除いた13項目と、選択乗務の識別子・乗務日・時刻・精算合計。元の設定JSON、GPS座標や軌跡、Firestore生データ全体は格納しない。キャンセルは印刷行で0円固定。未精算、未入庫、営業61件以上、計算不一致、不正金額、サイズ超過は拒否。
- `printStageAppendV1_()` はステージタブの名前と列見出しを固定照合し、サーバー側で認証済みとされるUIDがパケットのUIDと一致することを要求する。更新番号を鍵に**追記のみ**行い、同一版・同一SHA-256なら再送時に追記しない。**同じ版で内容違い・古い版の再送・期待していたステージ版と実際の最新版が違う（CAS競合）**場合は拒否。LockServiceの排他取得・読み戻し確認・書込失敗の不成功扱いを備える。別IDの行や旧版の記録は上書き・削除しない。
- `printStageReadLatestV1_()` はステージの同ID更新番号の最大値を読み戻し、UIDに結びついた転送ID・SHA-256・データ構造を検査してから印刷用派生データを返す。読み戻し時の改ざん・異なるUID・重複更新番号・破損を拒否。**SHA-256は整合性照合であり、認証・真正性保証の代替にはならない。**
- ステージJSONは**1版につき1行・1セル**に格納し、Google Sheetsセル上限より小さい30,000文字以下に制限。これを超える場合は分割未実装のため停止する。返り値はステージ登録状態・乗務ID・版番号のみで、乗車地や生データをログやPRへ出さない。

- GAS公開版の切替、既存帳票の参照式変更、FireStore本番Rules公開、管理者の日報原本移行、旧Google原本の削除はそれぞれ**個別の事前承認が必要**。本段階だけでは公開しない。

## 2026-10-21 第12段階：修正日報の既存Google印刷元への安全な再反映（未公開）

### 実装・合成データで確認済み

- `google-apps-script/PrintOnlyExistingSheetsReprintTransactionDraft.gs` を**ドラフトだけ**追加。第11段階の新旧V2確定版と現行4シートの**完全一致した旧版**を根拠に、件数・決済行数が変わらない修正についてのみ、同一IDの対象行を更新できる試作を実装した。行数の増減、同IDのGoogle旧同期原本との衝突、第三者が修正したセルは**自動更新しない**。
- 専用の新規監査タブ `TAXIAPP_印刷更新監査_V1` を**将来の隔離環境向けの設計のみ**定義（本番ファイルには作成していない）。記録は乗務ID・新旧更新番号・SHA-256・段階（`BEGIN/COMMIT/ROLLED_BACK/RECOVERY_REQUIRED`）だけで、個別営業や金額・住所・位置座標は記録しない。監査を先に追記し、保護された既存4シートの更新後にだけ `COMMIT` を記録する。
- 必須条件：**信頼済みサーバーの本人UID・Firebase最新原本/削除状態確認**と**印刷利用者の一時停止を保証するメンテナンス確認**の両方が真の場合に限る。Apps Script `LockService` はスクリプト間の排他であり、**Googleシートを見ている人の紙印刷は止められない**ので、単なるロックだけでは本番切替できない。
- 途中失敗時は、変更した各セルが「完全一致した旧版」または「今回の新版」に一致する場合だけ旧版へ戻す。第三者変更・破損・戻し失敗なら `RECOVERY_REQUIRED` のまま停止して管理者による確認を待つ。処理が中断して `BEGIN` が残った場合には、**別の専用復旧関数**でV2確定版の新旧SHAと現行Google印刷セルを照合してから戻す。何も根拠なく削除・全シート書換え・他IDへの干渉はしない。
- `COMMIT` 行を保存した後に確認応答が失われた場合、**自動で再更新・旧版差戻しはしない**。 `COMMIT_CONFIRMATION_UNKNOWN` として監査履歴の再読込を要求する（COMMIT済み行のあとに誤ってROLLED_BACKを書かない）。
