# TAXIAPP 印刷：既存Google補助簿を使った本番接続の準備状況

更新：2026-10-21 / PR #115（ドラフト、main未統合）

## 変更しないもの

- 正式な印刷は現在の `TAXIAPP_日報・補助簿印刷` の `補助簿印刷用` と `補助簿印刷用_2頁` を使う。
- `TAXIAPP_印刷操作!B15/B17/C17` と `TAXIAPP_乗務一覧!T:U` の従来の乗務選択・計算式、印刷幅・罫線・紙の設定・書式は変更しない。
- `TAXIAPP_同期原本`、端末内日報、Firestore原本、売上と乗車記録、既存の他人の乗務を削除・上書きしない。
- 既存GASの `syncPutV2_ → savePacket_` は印刷専用ではない。 `TAXIAPP_同期原本` 等も更新するため、Firestoreの日報を印刷するためには流用しない。

## 開発ブランチで検証した処理

1. Firestore原本・Google旧原本の同一IDと内容を読取専用で照合（完全一致を識別、不一致は停止）。
2. Firestore由来の印刷4ソースをV2形式へ変換してSHA・更新番号を検証し、分割して `COMMIT` で確定するステージ試作。
3. 新規IDの日報のみ、既存Google印刷4ソースの新しい空白行へ安全に追記（原本は不変更）。旧Google同期原本と同IDなら停止。乗務一覧を最後に追記して未完了の乗務を選択可能にしない。
4. 改版日報：過去の確定V2印刷版と現行印刷4ソースの対象行の完全一致を確認。営業件数・決済件数が変われば自動処理せず保留。
5. 件数が変わらない改版：**本番未接続の試作**で、印刷停止確認・本人の現行revision確認・監査ログBEGINの後に対象行だけ変更。失敗時は確認できる旧版へ差戻し、第三者変更や破損なら `RECOVERY_REQUIRED` で停止。途中中断時には別の復旧関数が旧確定V2版を根拠に差戻す。
6. COMMIT確認応答だけが失われた場合は状態不明として止め、**自動差戻し・二重更新しない**。すべての結果は紙への印刷許可を自動で返さない。
7. 実シートのヘッダー行を読み取り専用で照合済み：乗務一覧19列、印刷データ14列、決済内訳11列、集計5列。ユーザーの個別売上や住所の読み取り・書換えはしていない。

## 本番公開前に必要な実環境確認（未実施）

- Firestoreの**現在の本番用ルール**には、印刷側の安全確認が必要とする `privateDuties/{uid}/tombstones/{shiftId}` の読取条件がまだない。**開発用 `rules-drafts/firestore-trash.rules` にはある**が本番ルールへ自動反映しない。
- 実Firebase IDトークンの署名・失効の確認、管理者 `admins/{uid}` 権限確認、Firestoreの本人原本取得はモックでのみ検証。既存Google共通接続キーや自己申告UIDは本人認証として使わない。
- 現行ブラウザの `googleShiftPacket()` は `deriveRaw/pricing/settledTenderAmounts/totals` に依存する。**サーバーが読んだFireStore原本から同じ計算を保証できる信頼済み計算処理の実装・同値テストが未完了**。クライアントが送った売上の数字だけを本番用の正規データとして採用しない。
- 本番の既存Apps Script `Code.gs` の `applySelectedPrintShift()` は旧Google同期原本を `loadShift_()` で読むため、Firestore-only乗務への選択確認は本番に接続できていない。従来の日報・印刷機能を壊さず分岐する手順が必要。
- 将来の印刷V2ステージ用タブと再印刷監査用タブは**設計だけで、本番シートに作成していない**。これらがない状態では実V2転送は行わない。
- Google Sheetsの複数シートの更新は原子的ではなく、`LockService` はPC利用者の印刷を停止できない。**印刷停止を保証する運用・復旧手順と、ユーザーの了承**が必要。
- 安全な接続サーバーの実行環境は未決定。Cloud Functionsの導入は課金プランの変更や有料リソース発生につながるため、**無料を優先する方針では勝手に契約・デプロイしない**。現行Google Apps Scriptでの検証も認証・権限・公開設定の承認を要する。

## 利用者に確認が必要になる境界

**まだこのチャット・GitHub開発ブランチだけでできる試験は合成データ上で進められる。実際のGoogleスプレッドシートへのテスト転送、帳票の複製、新タブの追加、GAS公開版変更、Firestore本番ルールや認証・権限の更新は、事前説明と明示承認なしでは行わない。**

安全な次の実環境作業は、まず**本番とは独立した検証用Googleシートに合成データだけを流し、既存の補助簿2ページの式と印刷切替の整合性を確認**すること。コピーする場合も実日報・個人データを安易に複製・共有せず、元の本番ファイルに一切書込しない方法を選ぶ。

テストが成立した後で、管理者本人の同意の下に、本物の署名検証・Firebase/Googleのアクセス権限・ルール適用とGAS公開を**別途承認**してから進む。

最終報告では「実装済み・合成試験成功」「実環境未検証」「仕様のみ決定」「検討中」を混同しない。

## 2026-10-21 実Google Sheets・隔離合成コピーでの検証結果

**ユーザーが隔離コピーの作成と検証を承認した範囲のみで実施。元のGoogleスプレッドシートへの書込みは一切なし。**

- 原本：`TAXIAPP_日報・補助簿印刷`（既存運用ファイル、読み取り専用）。
- 検証用コピー：`TAXIAPP_補助簿_隔離検証_合成データのみ_20261021`（元と異なるスプレッドシートID）。Google Driveのメタデータで**shared:false、権限は所有者1人だけ**を確認。新たな共有設定・Apps Script公開・Firebase権限変更はしていない。
- 元ブックの**20タブを複製後、コピー内すべてのセルの入力値とメモをクリア**。元の非表示「日報」「過去データ」「旧テスト控え_RAW」「TAXIAPP_同期原本」等の実データは持ち込まない。保持するのは印刷2ページの数式345/381個、乗務一覧T/Uの数式、印刷操作5個の数式と選択チェック、印刷4ソースの列ヘッダー、印刷レイアウトの書式、一般的な見出しと固定番号のみ。氏名・住所を含みうる長い静的ラベルも保守的に再利用せず、印刷ページに「合成データ検証専用」と明示。**内容保持ではなく印刷方式の隔離レイアウト・式の検証コピー**である。
- 検証用コピーの既存印刷4ソースへ合成の37件（通常営業36件＋キャンセル1件）と複合決済72行、集計14行、乗務一覧1行を投入。旧Google同期原本は空白のまま保持。B15最新乗務で合成ID `shift-1792501200000-demo` がC17に選ばれ、補助簿1ページ目のD8=1000円、X23=36000円、2ページ目D8=0円かつ「キャンセル」と表示されることを**Google Sheetsの実際の数式評価**で確認。
- 手動選択 B15=false、B17=合成乗務ラベルでC17が同じID、X23=36000円と確認。試験後はB15=true・B17空欄に復元。
- 合成の日報を**同じ件数のまま金額修正**する試験として、印刷データ E2 1000→1100円、決済内訳 E3 500→600円、乗務一覧 I2 36000→36100円、集計 C2 36000→36100円・C15 43200→43300円を**検証コピー内だけ**変更。Google印刷のX23=36100円、D8=1100円へ更新されることを読み戻し。その後すべて元の合成値に差戻し、X23=36000円・D8=1000円・決済E3=500円・2ページ目キャンセルD8=0円を確認。

- 将来の接続試験に備えて、**隔離検証用コピーだけ**に非表示の `TAXIAPP_印刷V2_ステージ` と `TAXIAPP_印刷更新監査_V1` の2タブを追加。各9列の実GASドラフトと一致するヘッダーを持ち、**2行目以降は空白・書込み実績なし**。検証コピーは計22タブになったが、運用中の元ブックは20タブのままで両タブ未設置を再確認。
- 最終チェックでは、検証用コピーの `TAXIAPP_同期原本` と旧 `日報` の検査範囲は空欄、B15最新乗務の合成IDがC17へ選択、X23=36,000円、補助簿2ページ目37件目のキャンセル=0円。実Google V2ステージのApps Script実行や本番権限を付与したわけではない。

## 2026-10-21 第14段階：実アプリの集計と印刷V2金額契約の再確認

- 最新の実アプリ `index.html` の `googleShiftPacket()`・`totals()`・`pricing()`・`settledTenderAmounts()` の関数本体を直接抜き出し、**合成データだけ**で実行する回帰テスト `tests/print-v2-production-packet-contract.test.js` を追加した。フロント内のDOM/GPS/UI依存・決済入力インタラクションは合成スタブに差し替えているため、**実ユーザーが端末で入力した全料金を証明するテストではない**。
- 上記検証では、本番ブラウザが送る `TAXIAPP_SHIFT_V1` パケットに `meter`、`goFee`、`cashReceived`、`cashRemittance`、`etcRemittance`、`totalRemittance`、`paymentAllocated` の各金額が**存在する**ことを確認。第7段階V2のヘッダー列との項目欠損ではなく、独立した印刷側の**金額整合検証不足**が主要な課題だった。
- `server-drafts/print-stage-legacy-rows.js` の変換前検査を強化。印刷用「決済内訳」の受取額・会社算入額を集計し、実アプリ `totals()` に対応する `cashReceived`、チケットを除く `paymentAllocated`、GO手数料を含みUber配車手数料等を反映する `cashRemittance`、`etcRemittance`、`totalRemittance` を再計算・照合。不一致ならSHA-256作成やGoogle転送より前に停止する。
- `tests/print-stage-v2.test.js` に、現金受取・決済配分・納金合計・ETC等の集計を1円ずつ改ざんした場合や、GO手数料を誤って控除した決済内訳を拒否するテストを追加。従来の60件合成テストで `raw.AQ` にGO手数料がないのに集計 `goFee=200` を流用していた不整合も訂正した。
- **キャッシュレス＋実車高速の特殊ケースを修正**。メーター1,000円＋GO手数料200円＋実車高速500円をQRで全額1,700円回収すると、実アプリの現金納金計算式により `cashRemittance=-500`円、`etcRemittance=500`円、`totalRemittance=0`円が正しい。従来の印刷V2変換は負数を拒否していたため、**現金納金と総納金のみ負数を許容し、その他の料金や受取の不正な負数は拒否**。合成パケット→4シート派生データ→V2転送・読戻しまでを検証する。
- 依然として**印刷専用の信頼済みサーバー側料金計算そのものは実装・検証していない**。試験用ゲートウェイの `makeLegacyPrintPacket` は依存注入される抽象関数であり、ブラウザから送信されたJSONを正規原本として受け付けない。特に設定や日付によって計算が異なるGO/Uber・割引・高速/ETC・キャンセルと複合決済を、実Firebase原本から再計算する完成品にはまだなっていない。
- このチャットから現在操作できるGoogle Drive/Sheets連携では**Apps Scriptの実行・デプロイ専用操作は提供されていない**。検証用コピーへ合成セルを書き込んだ試験と、GASをNode VMで疑似実行した試験を、実Apps Scriptに直接接続したテストと混同しない。実GASの権限許可・公開、本人認証接続を必要とする前段階は引き続き保留。元のGoogle原本、Firebase本番Rules、GAS公開版、既存2ページ帳票は無変更。
