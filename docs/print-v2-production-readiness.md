# TAXIAPP 印刷：既存Google補助簿を使った本番接続の準備状況

更新：2026-10-21 / PR #115（ドラフト、main未統合）

## 変更しないもの

- 正式な印刷は現在の `TAXIAPP_日報・補助簿印刷` の `補助簿印刷用` と `補助簿印刷用_2頁` を使う。
- `TAXIAPP_印刷操作!B15/B17/C17` と `TAXIAPP_乗務一覧!T:U` の従来の乗務選択・計算式、印刷幅・罫線・紙の設定・書式は変更しない。
- `TAXIAPP_同期原本`、端末内日報、Firestore原本、売上と乗車記録、既存の他人の乗務を削除・上書きしない。
- 既存GASの `syncPutV2_ → savePacket_` は印刷専用ではない。 `TAXIAPP_同期原本` 等も更新するため、Firestoreの日報を印刷するためには流用しない。

## 開発ブランチで検証した処理

1. Firestore原本・Google旧原本の同一IDと内容を読取専用で照合（完全一致を識別、不一致は停止）。
2. Firestore由来の印刷4ソースをV2形式へ変換してSHA・更新番号を検証し、分割して `COMMIT` で確定するステージ試作。
3. 新規IDの日報のみ、既存Google印刷4ソースの新しい空白行へ安全に追記（原本は不変更）。旧Google同期原本と同IDなら停止。乗務一覧を最後に追記して未完了の乗務を選択可能にしない。
4. 改版日報：過去の確定V2印刷版と現行印刷4ソースの対象行の完全一致を確認。営業件数・決済件数が変われば自動処理せず保留。
5. 件数が変わらない改版：**本番未接続の試作**で、印刷停止確認・本人の現行revision確認・監査ログBEGINの後に対象行だけ変更。失敗時は確認できる旧版へ差戻し、第三者変更や破損なら `RECOVERY_REQUIRED` で停止。途中中断時には別の復旧関数が旧確定V2版を根拠に差戻す。
6. COMMIT確認応答だけが失われた場合は状態不明として止め、**自動差戻し・二重更新しない**。すべての結果は紙への印刷許可を自動で返さない。
7. 実シートのヘッダー行を読み取り専用で照合済み：乗務一覧19列、印刷データ14列、決済内訳11列、集計5列。ユーザーの個別売上や住所の読み取り・書換えはしていない。

## 本番公開前に必要な実環境確認（未実施）

- Firestoreの**現在の本番用ルール**には、印刷側の安全確認が必要とする `privateDuties/{uid}/tombstones/{shiftId}` の読取条件がまだない。**開発用 `rules-drafts/firestore-trash.rules` にはある**が本番ルールへ自動反映しない。
- 実Firebase IDトークンの署名・失効の確認、管理者 `admins/{uid}` 権限確認、Firestoreの本人原本取得はモックでのみ検証。既存Google共通接続キーや自己申告UIDは本人認証として使わない。
- 現行ブラウザの `googleShiftPacket()` は `deriveRaw/pricing/settledTenderAmounts/totals` に依存する。**サーバーが読んだFireStore原本から同じ計算を保証できる信頼済み計算処理の実装・同値テストが未完了**。クライアントが送った売上の数字だけを本番用の正規データとして採用しない。
- 本番の既存Apps Script `Code.gs` の `applySelectedPrintShift()` は旧Google同期原本を `loadShift_()` で読むため、Firestore-only乗務への選択確認は本番に接続できていない。従来の日報・印刷機能を壊さず分岐する手順が必要。
- 将来の印刷V2ステージ用タブと再印刷監査用タブは**設計だけで、本番シートに作成していない**。これらがない状態では実V2転送は行わない。
- Google Sheetsの複数シートの更新は原子的ではなく、`LockService` はPC利用者の印刷を停止できない。**印刷停止を保証する運用・復旧手順と、ユーザーの了承**が必要。
- 安全な接続サーバーの実行環境は未決定。Cloud Functionsの導入は課金プランの変更や有料リソース発生につながるため、**無料を優先する方針では勝手に契約・デプロイしない**。現行Google Apps Scriptでの検証も認証・権限・公開設定の承認を要する。

## 利用者に確認が必要になる境界

**まだこのチャット・GitHub開発ブランチだけでできる試験は合成データ上で進められる。実際のGoogleスプレッドシートへのテスト転送、帳票の複製、新タブの追加、GAS公開版変更、Firestore本番ルールや認証・権限の更新は、事前説明と明示承認なしでは行わない。**

安全な次の実環境作業は、まず**本番とは独立した検証用Googleシートに合成データだけを流し、既存の補助簿2ページの式と印刷切替の整合性を確認**すること。コピーする場合も実日報・個人データを安易に複製・共有せず、元の本番ファイルに一切書込しない方法を選ぶ。

テストが成立した後で、管理者本人の同意の下に、本物の署名検証・Firebase/Googleのアクセス権限・ルール適用とGAS公開を**別途承認**してから進む。
