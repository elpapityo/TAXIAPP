# TAXIAPP 日報保持・イベント同期・過去日報編集（決定済み仕様）

## 保持先と切替
- 通常の端末ローカル原本は**進行中の1乗務**または**入庫済み直近1乗務**のみ。
- 入庫後も直近の乗務は残す。次に出庫すると、その出庫日報が通常保持対象になる。
- 過去日報は本人UID配下のFirestoreから必要なときだけ取得し、既存の日報画面で編集する。専用の料金計算エンジンは作らない。
- **例外**：未同期、送信結果不明、競合中、オフライン編集中、復旧が必要な乗務は件数上限を適用せず端末に保持する。過去の現行端末原本は安全な個別移行・照合が完了するまで削除しない。
- 他の乗務の一時編集データによって進行中の乗務、GPS、下書き、端末設定を上書きしない。

## 同期契機
- 出庫、車両ステータス変更、支払確定、入庫時に対象の**1乗務**をFirestoreへ同期する。
- GPS測位・通常の文字入力のたびには送信しない。既存端末への随時ローカル保存は継続。
- オフライン中は操作を止めず、未送信を保持して次回同期契機/再接続で再試行する。入庫時には最終同期。
- 通信成功だけで完了とせず、Firestore本人UIDの対象原本をサーバー読戻しし、ID・版・内容が一致してから「保存確認済み」とする。

## 競合と編集
- 同じ乗務IDでサーバーと端末の内容が異なるときは自動上書きせず、双方の情報を保持して、ユーザーに「端末を採用」「サーバーを採用」「保留」を提示する。
- 更新番号CASにより、比較後に別端末から更新された場合も上書きを防ぐ。
- 過去日報は取得した原本を**一時編集用**に扱い、保存成功・サーバー読戻し後に一時データだけ解放する。
- 日報の検索・月間売上集計はFirestoreの本人データから行い、既存計算済み金額を利用する。

## 実装と本番反映の境界
- PR #119の保存/読戻し保護は実装中。本資料は決定済みの振舞いを整理するもので、端末の1件化や過去日報のオンライン編集が完成したことを意味しない。
- 旧Google同期原本、既存補助簿2ページ、正式計算式、旧営業記録、個人のFirestore認証設定を保護する。
- **mainへの統合、管理者の保存先切替、実データの移行・削除、Firebaseルール変更、本番Apps Script再公開は別途安全対策と事前承認が必要。**

## PR #119 追記：開発版の実装状況
- **実装済み・未公開**：本人Firestoreの指定日読取、現在乗務から独立した過去日報の営業明細修正（乗降地・乗降時刻・乗車距離・人数・メーター金額・配車/金種・一部高速料金・割引・Uber金額・複合決済の主要欄）。
- **安全策**：変更内容は本人UIDと乗務IDごとの端末控えに保持し、Firestore更新番号CAS、サーバー読戻し確認、異常時保留を維持。保存後も進行中の乗務に自動反映しない。既存の pricing()/deriveRaw()/paymentBreakdown() を呼び、別料金計算器は設けない。
- **競合表示**：本人の操作端末の設定から「端末版とFirestore版を比較」「端末を採用」「サーバーを採用」「保留」が可能。採用には従来どおり双方の暗号化バックアップを要する。
- **開発版に追加実装**：過去日報の営業記録（乗車・キャンセル・空車高速）の個別追加・削除、複数高速区間の区間別変更・追加・削除。既存 `makeDraft()`、`validateDraft()`、`deriveRaw()`、`TAXIAPP_HIGHWAY_SECTIONS.validate()/project()` を使い、CAS保存・読戻し確認後に修正控えを整理。操作で実記録を変更することはユーザーの明示操作によるもので、開発中の本番データには実行しない。
- **なお未完成・未検証**：日報画面の全編集項目との操作統合、実機での金額・支払・複数高速・営業追加削除の一連の検証、管理者の旧Googleから本人Firestoreへの正式切替、現行実データの個別移行と旧原本保護。本番Firebaseの権限ルールや既存Google補助簿は変更していない。合成コード検証成功を本番利用可能と扱わない。
