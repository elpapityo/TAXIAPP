# メーター型・複数項目同時記録の確認ポップアップ（2026-10-25決定）

## 目的・対象
- メーター型の「実車」専用ではなく、**1回の操作で複数の入力欄に日時・場所・距離などを記録するボタン**が対象。
- 既存コード上、実車開始（流し・迎車から・休憩後）、迎車受付、待機開始、空車高速開始、降車／支払いへ、迎車キャンセル、休憩開始・終了、保存確定などを確認表示の契機とする。単なる画面遷移・割引の1項目切替・入力破棄では表示しない。
- 記録処理を置き換えず、既存の日報・GPS・料金計算・Firestore同期から読み取った**登録済みまたは記録途中の値**を提示する。別の距離・金額計算エンジンは追加しない。

## UI（v0.3.167）
- スマホの横幅を超えない最大440pxのコンパクトなパネル。画面下寄りに重ね、距離項目のみ文字を大きくする。画面が横長の場合は右寄せ。
- 項目は必要なものだけ。既存の乗車・降車距離設定（`pickupDropDistance`）、受信時刻・人数・降車地等の表示ON/OFFを使用する。現行アプリで必須の時刻・乗車地は常時表示（この2項目に個別のOFF設定は存在しない）。設定OFFの任意項目は出さない。
- GPS・住所が取得中なら「取得中」、空欄で取得されなければ「未取得」。既存の `raw` や待機・休憩情報が更新されたら表示も更新する。ポップアップの閉鎖でGPS・住所処理は停止しない。
- 無操作で10秒後に閉じる。ポップアップ内で指・キーボード・ホイール操作があれば自動閉鎖を停止。手動「確認して閉じる」「修正する」で終了する。
- 修正は既存の「詳細入力・修正」を開く。保存済みレコードを開く場合も既存の履歴編集ドラフトへ移すだけで、Firestore原本を直接変更しない。
- 営業モード・UIDが変わったら確認表示を閉じる。閲覧専用への遷移後に修正ボタンで新しい編集データを作らない。
- 通常の詳細入力方式では表示しない。既存営業画面・保存イベント・GPS測位・料金・印刷は変更しない。

## 実装ファイルと検証
- `index.html`：小画面向けCSS・固定表示領域・確認のみのUI関数・既存メーター操作成功時の呼び出し。タイトル／初回画面Verはv0.3.167へ更新。
- ブラウザ構文確認、模擬DOMで実車／迎車／降車／休憩などの出し分け、距離取得待ちと値の更新、10秒自動終了、操作時停止、別UIDへの切替で閉鎖、閉じた場合の原本非変更を確認。
- 本番営業データ・Firestore Rules・Firebase Authentication・Cloud Functions・GAS・Google印刷帳票への書込なし。
- Android実機のGPS更新タイミング、画面縦横・ソフトキーボードとの見え方は本番端末未検証。

## 決定仕様との関係
既存アプリには必須の乗車時刻・乗車地を個別に非表示へ切り替える入力設定は存在しないため、この2項目は既存の必須入力のまま確認表示する。将来、正式に入力ON/OFF設定が追加された場合は、その同じ表示設定に確認ポップアップも追従させる。
