# TAXIAPP バージョン方針（2026-10-18）

## v0.3.49まで：従来の入力画面・方式の参照基準
- 営業入力は「空車・待機 → 乗車／アプリ迎車 → 乗車情報 → 降車・精算」の流れ。
- 現行コードには Googleログイン／Firestore操作権の試験実装が含まれている。過去版の存在を否定しない。
- UI試作ページの「従来入力（v0.3.49）」はこの入力操作の参考実装。保存・GPS・精算計算・サーバー認証は接続しない。

## v0.4.0から：サーバー認証方式を正式な本体バージョンとして扱う
- 以後の本体のサーバー認証・操作権切り替え・複数端末での閲覧／編集制御の設計は **v0.4.0 系** として進める。
- UI候補は「1画面入力」「段階入力」「詳細入力」「従来入力」の4つを比較し、端末サイズの選択と独立させる。
- 本体への統合までは、営業記録・IndexedDB・Googleシート・Apps Script・Firestoreルールを変更しない。
- 一連の動作検証と既存データ保護を確認した時点で本体のバージョン番号を更新する。UI試作の追加だけで本体を自動的にv0.4.0へ上げない。

## 設計原則
- 乗務データの意味や料金計算は表示方式に依存させない。
- 利用者別の入力モード選択を想定し、同じ日報データを複数のUIから扱えるようにする。
- スマホ（手持ちなしの車載操作）は原則1カラム、下部メニュー固定。折りたたみ・タブレットは別の表示幅を選択できる。
