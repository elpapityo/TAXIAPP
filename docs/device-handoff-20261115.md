# TAXIAPP｜端末間データ引き継ぎ（2026-11-15）

## 操作手順

1. **旧端末**：「その他」→「データの引き継ぎ」→「引き継ぎ準備・保存確認」。現在の未入庫乗務を終了しない。
2. 端末内保存、設定のサーバー読戻し、本人日報の同期（CAS・内容・更新番号）が成功したときだけ旧端末を閲覧専用へ切り替える。
3. **新端末**：同じGoogleアカウントでログインし「その他」→「データの引き継ぎ」へ。閲覧専用なら「この端末で操作する」。すでに操作権を取得済みだが未入庫乗務が出ない場合は「未入庫の乗務を読戻す」。
4. 操作端末が切り替わり、同じ乗務ID・営業件数・最後の営業内容を確認できてから入力を再開する。
5. **旧端末はログアウトや日報削除をしない。** 戻す場合も新端末で保存確認を行い、旧端末で操作権を再取得する。

## 安全条件

- 同一UIDに限定。既存 `deviceSessions/{uid}` の操作権監視と本人Firestore/旧Googleの同期を再利用する。Firestore認証・ルールや印刷帳票は変更しない。
- クラウド同期がOFF、通信断、ローカル保存失敗、月間設定の読戻し失敗、日報の同期失敗、送信結果不明、CAS競合、記録が通信中に変更された場合は操作権を手放さない。
- 全ての端末保持中の日報の同期状態を確認する。未同期の原本は件数上限なく保護し、引き継ぎのために削除しない。
- 新端末に完了済みのローカル乗務があればそのまま保護し、本人Firestoreの**未入庫乗務を1件だけ**追加取得する。同名IDがある場合は内容比較し、差異があれば受信停止。異なる未入庫が並存する場合も自動統合しない。
- 旧端末が自ら閲覧専用に切り替えたことは端末内で保持し、再起動後に意図せず編集権を復帰しない。再取得は既存サーバー承認が必要。
- 実際の端末間でGPSの計測状態が継続することまでは保証しない。GPSの端末固有の測位・許可設定を新端末で確認する。

## 未完成時の扱い

新端末で目的の未入庫乗務が表示されない場合や古い端末内乗務が表示されている場合は、必ず「未入庫の乗務を再照合する」を押してから、クラウド読戻しの状態・ID・件数を確認する。旧端末に残る原本は削除しない。衝突時は元データを保持し、人間が内容を比較して判断する。
