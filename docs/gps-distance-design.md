# TAXIAPP GPS走行距離自動入力：コード調査・設計方針

調査日：2026-10-16
状態：**2026-10-16 ブラウザ版GPS試験計測 v0.3.26。停止・再開、古い測位イベント、停車中のGPSずれに対する安全対策を追加。実機走行検証は未完了。**
対象：TAXIAPP ブラウザ版（2026-10-16 現行ソース）

## 1. 調査の結論

- HTTPSサイト上で許可を受け、`navigator.geolocation.watchPosition()` によって**画面表示中の継続的位置取得**は実装可能。
- 緯度経度の時系列から走行距離の推定値を計算し、既存のトリップ距離欄へ反映することも可能。
- ただし通常のブラウザ／PWAでは画面消灯中や他アプリ表示中に、位置更新を継続して受け取れる保証が**ない**。W3C仕様は非表示ドキュメントへの位置更新を保留・破棄する方針。運転業務の走行距離を「画面消灯を含めて自動で全量記録」することはブラウザ版だけでは保証できない。
- 画面消灯中も確実に追跡する設計には、将来のAndroidアプリ化時に**location foreground service（持続通知）**を使う案が適する。ただしAndroid権限・OS制約・バッテリー設定および実機検証が必要。
- APIキー付きGoogleマップを使わなくても、距離計算は緯度経度だけで実現できる。地図表示は後から任意機能にする。

参考：
- [MDN watchPosition](https://developer.mozilla.org/ja/docs/Web/API/Geolocation/watchPosition)
- [W3C Geolocation API](https://www.w3.org/TR/geolocation/)
- [Android location permissions and foreground service](https://developer.android.com/develop/sensors-and-location/location/permissions)
- [Android 14 location foreground service restrictions](https://developer.android.com/about/versions/14/changes/fgs-types-required)

## 2. 既存コードで確認した事実

- 現行GPS取得は待機場所と乗車・降車住所の `getCurrentPosition()` のみ。走行距離用の `watchPosition()` は未使用。
- `newShift()` は乗務開始状態を作る。現在の `startShift` 処理は出庫距離の入力を必須にしている。
- 既存RAW A:AR 44列の距離欄：
  - `F` 乗車時／迎車先到着時のトリップ表示値
  - `L` 降車時のトリップ表示値
  - `S`／`V` 実車高速の乗／降インターのトリップ表示値
  - `AB`／`AE` 空車高速の乗／降インターのトリップ表示値
  - `X`／`AJ` 等は高速区間距離として **前述のトリップ値から算出される派生項目**。直接GPSで書き換えない。
- `waiting.odometer`、`shift.startingOdo`、`shift.endingOdo` も距離関連の入力・保存欄。
- `beginRide` が流しの乗車開始、`boardDispatch` が迎車後の乗車開始、`cancelDispatch` がキャンセル、`endShift` が入庫。
- 現状は `stampAlightIfNeeded()` がメーター金額 `K` の入力時などに降車時刻を確定できる。**実際に降車した瞬間とは限らない**ので、実車→空車の距離区分境界としてそのまま採用しない。
- `cancelDispatch()` は旧互換動作のため、過去の降車距離 `F/L` をキャンセル欄に継承する場合がある。GPS方式ではキャンセルの受信・解除時刻と距離を別に保持し、乗務間の移動を失わないようにする。
- IndexedDB（代替localStorage）に `model.shifts` が保存される。Googleへの送信では `googleShiftPacket()` でRAW、決済、集計、元の乗務JSONを転送する。受信先の `TAXIAPP_同期原本` は文字数上限（30,000文字×20チャンク）があるため、毎秒のGPS全点を乗務JSONに加えない。

## 3. 距離状態モデル案

乗務開始時、車両側トリップを乗務員が0kmにリセットし、アプリも0.0kmからスタート。

- `shift.gpsTrip`：計測状態、累計距離km、最新の有効GPS時刻・緯度経度・精度・測位状態、中断／欠測期間、手動補正履歴、実車／空車のGPS計測区間、必要なら要約した地点情報。
- `record.meta.gpsDistance`：乗車時・降車時の推定トリップ値、営業区間GPS実車距離、測位品質、手動入力の有無。
- 既存RAWの距離欄は現在のトリップkmから自動記入するが、元の欄とデータ互換性は維持。既存レコードの距離は勝手に再計算しない。
- 緯度経度間の距離を地球楕円体近似／haversine計算で積み上げる。道路距離とGPS直線距離は同じではない点を表示する。
- 位置データの時刻・精度 `accuracy`・移動速度・突然のジャンプ・古い位置を検査し、明らかな異常値は加算せず状態を「低精度／取得中断」にする。
- 保存頻度は実測値で調整。全GPS地点を無制限に保存すると容量上限・電池消費・個人情報保護の問題が生じる。

### 手動補正

例：GPS 5.2km→実車トリップ5.5kmに訂正した時点で、**表示累計を5.5kmに変更**し、新しいGPS基点を確立する。その後GPS+3.1kmで8.6km、さらに+2.4kmで11.0km。

訂正履歴に修正前／修正後／修正時刻／理由（任意）／測位品質を保存。以前の移動区間を上書き・再分配しない。実車・空車のGPS積算と手動補正差分は分離して保持し、距離区分が不明な補正を推測で実車または空車へ加算しない。

## 4. 走行状態の切替案

| 操作・状態 | GPS距離区分 | 確認事項 |
|---|---|---|
| 出庫後／流し／待機／迎車中 | 空車 | 迎車と通常空車は必要なら補助区分に分割 |
| お客様が乗車／流しで乗車 | 実車 | `boardDispatch`／`beginRide` の時刻で区切る |
| お客様が降車 | 空車 | 現状のメーター金額入力では遅れる恐れ。正確な降車操作／時刻を別途検討 |
| 迎車キャンセル | 空車のまま | キャンセルで実車へ入らない |
| 入庫 | 計測終了 | 入庫距離の検証・未計測区間の確認 |

区分変更は**時刻付きイベント**として保存し、位置取得イベントの遅延や記録の二重計上を防ぐ。

## 5. 計測の欠測・補正

1. GPS位置更新が長時間ない／精度不十分／速度異常なら、最後の確定地点から離れた位置までの直線距離を**自動で足さない**。
2. 「GPS停止中」「前回有効測位から○分」「未計測区間あり」「車両トリップで手動補正してください」などを表示。
3. 手動入力が行われた場合、距離を補正して再びGPS計測を継続。測位が復活しても以前の穴を推測で埋めない。
4. `document.visibilitychange` でバックグラウンド・復帰を検知し警告する。ただしバックグラウンドでのGPS継続を保証する仕組みにはならない。
5. 電波／通信断は区別して扱う。衛星測位の取得自体は通信不能時でも可能な場合があるが、端末や環境による。
6. 地図や経路表示は**任意**とし、OpenStreetMap等の利用条件・タイル負荷・個人情報保護を確認してから追加。

## 6. Google保存との整合

- 現行 `model.shifts` 内にGPS累計・補正履歴・実車／空車区分結果を保持し、既存の `googleShiftPacket` で送信可能な軽量サマリーとして保存する。
- 44列の既存帳票は壊さない。RAW距離点は従来どおりに送信し、GPS固有の測位品質や補正履歴は別項目／別シートで管理する。
- 詳細なルート点を必要に応じて保存する場合、現行JSONの容量制約を先に解消し、別ファイル等で管理する。Googleドライブ一元管理案との整合を実装時に決める。
- 既存乗務データはGPS未計測扱いで保持し、GPS距離を後から捏造しない。

## ブラウザ版 v0.3.25 で実装した機能

GitHubファイル：`index.html`、`gps-trip.js`、`gps-trip-ui.js`。

- 新しい乗務の出庫時トリップ入力の初期値を0.0kmとし、「GPS試験計測も開始する」のチェックを標準表示（外せば従来どおり手入力）。
- 出庫・入庫画面、乗務入力画面にGPSトリップの累計・GPS実車距離・空車距離・GPS欠測件数を表示。
- 位置情報APIの継続取得（`watchPosition`）で位置を監視。精度が悪い／タイムスタンプが古い／異常速度／測位途切れを検知したら自動積算しない。
- ブラウザ非表示で監視を一旦止めて欠測を記録し、再表示では位置の基準を取り直す（距離を補完しない）。
- **測位の欠測が1回でも発生した場合、車両トリップへの手動補正が完了するまでGPS値の距離欄への自動転記を停止。** 復帰したGPSが移動距離を積算していても、未計測の穴を黙って確定値にしない。
- 乗車ボタン／迎車から乗車でトリップ地点 `F` を記録し、GPS距離区分を空車→実車に切り替える。
- 「お客様が降車（GPS実車距離を確定）」のボタン、または旧来のメーター金額入力で `L` を取得し、距離区分を実車→空車に戻す。降車ボタンを使用するほうが分類精度が高い。
- 待機時距離と入庫時距離は稼働中のGPSトリップ推定値を自動記入。実車高速／空車高速の各トリップ欄は「GPS距離を入力」の操作に対応し、高速の入出時刻を現在時刻で記録すると対応する距離欄にも反映する。
- 距離入力欄 `F/L/S/V/AB/AE`、待機距離、入庫距離を手動で訂正した際、修正値から新しいGPS測位基点で積算を再開。変更前後の差と時刻・修正元を100件以内で保持。
- GPSの走行ログは軽量サマリーのみ保持（全地点の無制限保存なし）。GPS値は乗務データの `gpsTrip` と各営業の `meta.gpsDistance` に保存し、Googleへ乗務送信する際の原本JSONにも含める。
- 営業履歴・日報集計・営業状況でGPS実車・空車距離と未計測件数を確認できる。
- キャンセルの0円処理、GO・Uber手数料、帳票売上、印刷用スプレッドシートの計算式は変更しない。
- **位置情報が取得できる実機での継続運転テストは未実施**。これは試験機能であり、車両トリップを正として照合・補正する。

### 試験手順

1. HTTPS公開版 `https://elpapityo.github.io/TAXIAPP/` を再読み込みする。
2. 次回出庫時、車両のトリップを0kmにする。アプリの出庫トリップも0.0km、GPS試験のチェックが入っていることを確認して出庫。
3. Android/Chromeの位置情報を許可し、GPSトリップ表示が「計測中」になることを確認。
4. **運転中にスマホ操作しない。** 停車後に実際のトリップとGPS値を比較する。異なる場合は「この距離から計測を続ける」で補正。
5. 迎車は空車、乗車操作後は実車。降車時はメーター入力より先に「お客様が降車」ボタンを停車中に押す。
6. 画面消灯／他アプリ表示後は「計測中断」の表示を確認し、失った距離は車両トリップで補正する。
7. 入庫時は累計GPS推定値と車両トリップを確認して、必要なら手動補正の上で保存する。
8. 補正履歴・欠測件数を確認し、必要ならGoogleシートへ乗務を送信（Apps Scriptの受信デプロイは従来の設定を利用）。

### 2026-10-16：v0.3.26での追加検証・修正

- 手動でGPSを停止→再開した場合は、停止期間の距離が不明なため「未計測区間あり」に変更。車両トリップを確認・手動補正するまで自動転記しない（旧v0.3.25で停止した乗務にも対応）。
- ブラウザでGPS監視を停止／再開・非表示復帰した際、**古いwatchPositionの遅延コールバックを無視**する。古い受信GPSが新しい計測区間を汚染しない。
- GPSが停止速度（0.7m/s未満）と通知している場合、25m程度の位置ずれを走行距離に加算せず、極端な位置移動は中断扱いにする。
- `tests/gps-trip.test.js` の21個のアサーションを再実行しすべて成功。模擬watchPositionの停止→再開・新旧通知の分離・画面非表示・手動補正・GPS静止位置ずれをテストし11条件に成功。
- `tests/gps-trip-ui.test.js` を追加し、将来の変更でも上記の回帰テストができるようにした。
- 既存の売上・GO/Uber手数料・印刷用スプレッドシートには計算上の変更なし。GPSの座標・距離は従来どおり端末内に保存し、乗務の送信時に元データへ含める。
- 実際のスマートフォン画面消灯中に正しくGPSを連続記録できる保証は**ない**。移動中の操作は禁止し、停止時にトリップ照合を行う。

## 7. 実装段階

1. **ブラウザ版GPS試験モード（実装済み／実機検証待ち）**：画面表示中の `watchPosition`、有効測位判定、速度異常除外、トリップ0.0km、手動補正・再基準、測位中断警告を実装。旧手動入力モードは残す。
2. **営業連携**：出庫／迎車／乗車／降車／キャンセル／入庫のイベントにGPS距離を関連付け、F/L/S/V/AB/AE、待機・入庫距離、営業別実車／空車／一日全体の集計と履歴へ反映。実車終了境界のUIは実機で検証。
3. **永続化・送信**：IndexedDBで軽量チェックポイント、手動補正ログ、受信スキーマの拡張、JSON・CSV互換、既存データとの回帰テスト。
4. **Android長時間計測版**：ブラウザの限界が実務に支障となる場合、ネイティブのlocation foreground serviceを採用し、画面消灯時・別アプリ中・圏外時の実機テストを行う。

## 8. 結論・未決事項

- **無料のGPS距離推定と既存欄への反映は可能**。地図APIは必須ではない。
- **画面消灯中を含む安定した全行程のGPS追跡は、現在のブラウザだけでは保証不可能**。その前提で距離の欠測表示と手動補正を必須にする。
- 実車／空車は**営業操作の切替に沿って**分類可能。ただし真の降車時刻とアプリのメーター金額入力時刻が違う問題を解決してから本実装する。
- 測位の精度閾値・更新間隔・バッテリー消費・スマホ機種ごとの挙動は、運転停止中の安全な試験と実車走行の事後照合で確定する。
- 過去データを変更せず、距離計測OFFや手動専用モードへ戻せる構成を守る。
