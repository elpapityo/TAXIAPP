# TAXIAPP メーター型・複数項目一括記録の確認表示（2026-10-25）

## 仕様
- メーター型入力で、**ボタン1回の操作が複数の営業記録欄を同時に変更した場合**に、小さな記録確認カードを表示する。実車開始だけに限定しない。
- 流し乗車・アプリ迎車後の乗車・迎車開始・待機・降車／精算移行・キャンセル・空車高速・休憩・営業完了など、既存のメーター型操作のうち複数項目が記録されるものを対象とする。既存処理結果の前後差分が2項目未満なら確認を表示しない。
- 表示する値は既存の `shift.draft.raw`、`shift.records`、`waiting`、`breakActive` 等から**読み取るのみ**。乗車の走行距離（`raw.F`）は大きく表示。降車時は `raw.L` を同様に扱う。距離・時刻・住所・人数の従来設定を尊重し、OFFの項目を確認カードに含めない（乗車／降車の時刻・住所は現在の入力設定上必須なので通常はON）。
- GPS・住所取得中は「取得中」、取得できないときは「未取得」と表示。既存 `refreshDraftGpsFields`、`refreshWaitView`、外部GPS値取得後に同じカードの表示だけを更新する。閉じてもGPS測位や住所変換処理は継続する。
- 無操作なら10秒で閉じ、カード内のタッチ・クリック・ホイール・キー入力・フォーカスで自動終了停止。「確認して閉じる」で即終了。「修正する」は既存の `.meter-details`（営業完了後は既存 `editRecord`）へ移動する。
- スマホ画面の右下に幅最大315px、表示高さ最大48dvhの非モーダル確認カードとして表示。営業画面全体を覆う背景レイヤーは設けない。大きな一覧・別画面・余計な常設ボタンを増やさない。
- UID切替・他画面への移動時にはカードを閉じ、別人の内容を残さない。
- **既存の日報計算、料金、距離算出、GPS記録、保存・Firestore同期のエンジンは一切変更しない**。確認カードには新規保存・書込機能を持たせず、二重登録しない。

## 変更ファイル
- `index.html`：メーター型の記録操作検知・既存原本の読み取り表示・非モーダルUI・表示更新・版表示 `v0.3.167`。
- `meter-confirm.js`：カード表示・10秒タイマー・触れたときの停止・表示更新・閉じる／修正イベント。
