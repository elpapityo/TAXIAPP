# TAXIAPP｜位置共有 独立試験版（第1段階）

## 先行実装
- 既存Googleログインを使う独立画面。別アカウント不要。
- 既存の出庫・入庫データを読取専用で確認し、営業中だけ現在位置を共有する。
- 公開初期値ON。非公開時は管理者を含め他者から不可視。
- 登録利用者の地図、5つの営業状態、一覧、現在地ボタン、5分更新切れ非表示。
- 走行時15秒、停止時90秒を送信目標とする。ブラウザ表示中のみGPS取得。
- GPS位置飛び検出の75m/sは仮の閾値。実機データで検証が必要。

## ブランチで新たに実装した処理（実機未検証）
- GPS履歴の約30秒間隔ローカル保存、乗務別静止地図、UTF-8 BOM付きCSV、日本時間の出庫日時を含むファイル名。
- 入庫時・アプリ再表示時・通信回復時・本人の再送操作を契機としたクラウド履歴保存・再送。さらに利用者の明示操作で保存済みクラウド履歴（直近最大40乗務）を取得し、端末コピーの整理後も地図・CSVを表示できる設計を追加。送信失敗時はGPS履歴を端末に保持する。
- 入庫済み乗務IDと点列のSHA-256で同一内容を識別。サーバー保存後の読戻しでハッシュと点数を照合し、確認後のみ「保存済み」にする。異なるサーバー原本を上書きしない。
- サーバー側の削除済みマーカーを確認し、削除済み履歴を再送しない。保存確認から7日後のみ端末内の保存済みコピーを整理する。
- 公開GPS送信と非公開操作の書込みを直列化して、通信中の公開再開を避ける。

## 必ず区別する点
- コードは作業ブランチ上。現行mainと公開版は変更しない。
- 現行firestore.rulesはgpsPresence、gpsSharePrefs、gpsHistory、gpsHistoryTombstonesを許可していない。
- docs/gps-sharing-firestore.rules.fragmentは未適用の提案である。
- Firestore本番ルール・認証権限の変更には別途事前承認が必要。未適用の案は履歴作成のみ許可し、管理者の他者閲覧はサーバー監査の強制設計が完成するまで閉じておく。
- 現時点でクラウド位置送信・他者閲覧・端末保存履歴・クラウド履歴の実読出しはブラウザ／実機未検証。JavaScript構文検査および同期モック試験のみ成功。
- 既存日報原本、売上、料金、高速、GPSトリップ、印刷は変更しない。
