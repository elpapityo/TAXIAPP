# TAXIAPP 管理者PC：テストアカウント削除管理

**状態：開発ブランチのコード。GitHub main・Firebase本番への反映なし。本番アカウント削除は未実施。**

## 2026年10月25日 管理者が登録一覧に表示されない問題の修正

- 原因は PC 管理ページが `users` のみを一覧取得していたこと。Google認証で権限を確認できる管理者でも `admins/{uid}` にしか登録がなければ「0件」になっていた。
- `users` と `admins` の両方をサーバーから取得し、Firebase AuthのUIDをキーに重複を除いて一つのアカウント一覧に表示。管理者本人は `users` 未登録でも「管理者（自分）」として必ず一覧に表示する。
- 管理者本人は、自身の `privateDuties/{uid}/shifts`（Firestore日報）と `accountSettings/{uid}` を、**既存の本人UID読み取りルールによりCloud Functions未配信でも直接閲覧**できる。他の管理者・一般利用者の原本は引き続き認証済み管理者Callableを利用する。**旧 Google Sheets 日報はFirestoreの一覧に含まれず**、TAXIAPP本体／従来のGoogle帳票で参照する。データがないと誤解しないよう画面で区別する。
- 管理者レコードについては、アカウント完全削除・テスト用指定・個別ゴミ箱移動を画面側でも無効化。サーバー側の管理者UID削除拒否は従来どおり維持する。
- 変更は管理 PC ページの表示のみ。Firestoreアクセスルール、既存の管理者原本保存先、移行設定、計算、帳票への変更なし。
- **公開・本番操作は別途承認が必要**。Firebase Functions未配信の場合、表示一覧の修正は使えるが、管理専用Callableによる詳細閲覧は利用できない。

## 使い方

- 管理者がPCの `account-admin.html` を開き、Googleでログインする。サーバーの `admins/{uid}.enabled === true` が確認できなければ管理画面は利用不可。
- 管理画面は登録済み `users` と `admins` のオプチャネーム・UID・状態・テスト指定を重複なく一覧表示し、絞り込みできる。最初の150件まで表示（人数が増えれば後でページングを実装）。
- 対象を選び、**UIDを完全一致入力＋取り消し不可の確認**後、サーバーから日報件数・設定・操作端末情報を照合する。
- 合成・テスト用と管理者自身が確認できたアカウントだけを「テスト用として指定」する（管理者Google再認証が必要）。既存営業データを持つ実利用者を指定しないこと。
- テスト用として指定した利用者は再度読み直し、削除前プレビュー後、UIDの一致、確認チェック、`完全削除` の文字入力、Google管理者再認証を経て削除を実行する。

## データの削除範囲

Cloud Functions側で、**管理者本人または管理者登録履歴のあるUIDは必ず拒否**する。管理者UIの表示制限だけに依存せず、サーバー側が `admins/{uid}` を確認する。

削除対象（指定した本人UIDのみ）：

- `privateDuties/{uid}` と配下の `shifts` 等（recursiveDelete）
- `accountSettings/{uid}`
- `deviceSessions/{uid}`
- Firebase Authentication の同じUIDのアカウント
- `users/{uid}` の個人情報（オプチャネーム・各プロフィール項目）

削除後は `users/{uid}` に **`status: 'deleted'` と `deletedAt` の最小限の再登録防止記録だけを保持**する。完全にUID記録まで残さない方式では同じUIDが再登録できてしまうため、ここは安全保護の例外。

**旧管理者のGoogle Sheets/Apps Scriptの原本・計算式・帳票は触らない。** 他のUIDのデータは削除しない。端末のIndexedDB、オフライン原本、本人が外部保存したJSON、別端末のローカルバックアップは遠隔削除できない。本人端末のローカルデータの手動整理は、該当UID・端末を確認して別工程とする。Firebase Authenticationを消してもGoogleそのもののアカウントは削除しない。

## 保護と失敗時の再試行

- Firebase AuthトークンのUIDと `admins` の権限を **Cloud Functions内部で毎回確認**。
- 完全削除時は管理者の5分以内の再認証、対象UID一致、同じオプチャネーム、照合時と同じ日報件数、`testOnly === true` を必須とする。
- `users/{uid}.status='deleting'` をサーバートランザクションで先に設定して、当該UIDからの新たなクラウド読書きと旧UIDの自動再登録を止める。
- Auth削除などで途中失敗した場合は `status='deleting'` のまま保持し、管理者が件数を再照合してから再実行できる。失敗したからといって無断で原本を復活・上書きしない。
- Googleで**再び新しいFirebase UIDのアカウントを作った場合は、別の新規登録として扱われる**。この機能はアクセス禁止・ブラックリストではない。

## 導入条件（本番未承認）

1. 本番のFirestoreアクセスルール、UID別データ、対象ユーザーのテスト指定と、利用者のバックアップ方針を確認・保存する。
2. 本番とは別のFirebase検証用プロジェクトまたは実営業記録を含まない専用試験環境で、管理者・利用者・削除失敗復旧の実接続テストを実施する。
3. **Cloud Functionsの導入はFirebase Blazeプランなど追加料金が発生し得るため、追加料金・新契約・本番IAM/認証・デプロイは個別事前承認が必要。**
4. 別承認後、Firebase CLIでログインし `npm --prefix functions install` 等の依存導入。デプロイは対象プロジェクトを目視確認し、`firebase deploy --only functions:account-admin --project taxiapp-2b6bd`。この `firebase.json` はFirestoreルールのデプロイを含まない。
5. 本番公開前に2つ以上の**合成アカウント**で、本人/他人の分離、日報件数、削除／削除失敗の復旧、管理者・旧Google原本の不変を検証する。


## 管理者による各利用者の日報・設定の閲覧と個別削除（追加機能）

**実装段階：開発ブランチ／本番未反映。** 同じPC管理ページの対象アカウントから操作する。

- 「この利用者の日報を表示」で対象UIDのFirestore日報概要を50件ずつ取得。1乗務を選ぶと、乗車記録・金額・住所・GPSを含む日報原本の内容を読み取り専用で表示。閲覧時に料金や距離は一切再計算しない。
- 「この利用者の設定を表示」で該当UIDの保存済み設定だけを表示。表示をローカル保存・外部送信しない。
- 閲覧専用CallableはリクエストごとにFirebase Authの管理者UIDと `admins/{uid}.enabled` を**信頼済みバックエンドで再照合**する。Firestoreのブラウザ向けルールを管理者の全UID閲覧に拡張しない。
- 閲覧操作と日報のゴミ箱移動は `adminAccessAudit` に「管理者UID、対象UID、対象乗務ID、日時、操作名」を記録。個人の住所・売上・GPS・認証トークンは監査ログに複製しない。
- 「この1乗務をゴミ箱へ移す」は**入庫済みの本人の日報1件だけ**を対象。日報を表示し、対象UIDと乗務IDを確認し、乗務ID再入力・確認チェック・Google管理者再認証を経てサーバーで処理する。管理者アカウントの原本・進行中乗務・他のUIDの原本は操作できない。
- サーバートランザクションで原本の `revision` が表示時と一致するか（CAS）確認し、**内容は変更せず `trashed:true`、更新番号+1** にして通常の日報一覧から外す。既存のゴミ箱・復元と整合する。料金・手数料・売上の再計算やスプレッドシートへの書き戻しはしない。
- **個別削除は復旧可能なゴミ箱移動であり、完全消去ではない。** 乗車記録1件だけの削除や本番原本の物理削除は今回の対象外。データを物理削除する場合は、利用者の未同期端末原本・バックアップ・移行状況を確認し、個別の本番削除承認が別途必要。
- 管理者閲覧の対象には個人の位置履歴・乗車記録が含まれる。業務目的・必要最小限の閲覧とし、本人への説明・プライバシー表示・運用権限を正式公開前に整える。管理画面を公開しても Functions の本番配信なしでは利用できない。

## 復旧方法

- 誤った新規デプロイを停止する場合はCloud Functions側の該当管理用関数を無効化・削除し、必要に応じて以前の版へロールバックする（Googleデータや他のFunctionsは削除しない）。
- すでに消したAuthアカウントや日報は**自動復元できない**。削除するアカウント個別の暗号化された検証用バックアップと復元手順がない場合、削除操作を本番で有効にしない。
- テスト指定はFirestoreの `testOnly` フラグ。これはユーザーアプリから変更できない。管理画面の再認証済み管理者バックエンドだけが設定できる。
